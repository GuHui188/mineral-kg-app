二、用什么模型、提示词或脚本抽取？
脚本：extract_triples.py（本包内）。运行 --print-prompt 生成 Schema 约束提示词：
限定 5 类实体、10 种谓词，注入已知实体标准名，要求逐条给出证据句、禁止推测。
模型：Kimi（Moonshot AI）大模型，按提示词逐篇抽取，输出 JSON。
抽取方式：LLM 抽取 + 规则对齐（extract_triples.py --align 做实体对齐与非法谓词拦截）。
说明：未调用 API 密钥等工程化环境，抽取在模型对话界面完成；模型版本号未记录。

三、哪个文件是原始输出，哪个是人工修改后的结果？
原始输出（模型返回后未改动）：llm_outputs/ 目录下 7 个 JSON（按来源编号命名）。
对齐合并结果（程序处理，未改判定内容）：new_triples.csv（65 条，含 NEW: 占位标记）。
人工判定表：audit_sheet.xlsx（含 人工判定 / 判定理由 / 核对者 / 处理建议 / 证据位置 列）。
人工处置后的入图就绪版：new_triples_v2.csv（占位 ID 替换为正式 ID、
  import_flag 入图标记、support_of 重复标注、valid_from/valid_to 时间限定）。
四个版本构成"原始输出 → 程序对齐 → 人工判定 → 入图处置"的完整链条，均可对照复查。

四、人工核对如何进行，现有评估指标怎样计算？
核对方式：4 人交叉分工，按 audit_sheet 的 evidence 列回查 policy_texts/ 原文逐条判定：
  李天语 16 条（S11+S13）、顾潓 19 条（S12+S23）、曹子素 20 条（S20+S21）、B 同学 10 条（S24）。
判定规则：正确 / 部分正确 / 错误 三档，判定理由逐条留痕。
指标计算：audit_and_metrics.py score 读取判定表自动计算——
  严格准确率 = 正确数/65 = 0.708；宽松准确率（部分正确计 0.5）= 0.769；
  P = 0.708；R = 0.793（gold 标准三元组总数 58，由 B 逐篇精读原文按 Schema 口径认定，
  每篇数值写在 audit_sheet 该篇首行 gold_count 列）；F1 = 0.748。
其中 5 条（E0003、E0021—E0023、E0035）经 D 组验收复核，补充裁决为：
  原文证据不足（判错维持、不入图），但事实成立且 A 组维表已收录，自动边保留。
