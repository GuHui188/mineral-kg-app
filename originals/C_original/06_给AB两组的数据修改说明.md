C 的导入是"清库重建 + 配置驱动"：数据行增删**不需要改代码**，重跑一条命令即可。
唯一要改代码的是"新增关系类型/新增标签"，那也只有几行。
**所以两组可以各改各的，不用互相等，也不用等我。**

## 1. 给 A 组（数据覆盖与口径）

### A1 ★ 8 家企业没有任何关系边，入图后是孤立节点（P1）

**证据**：这 8 个 `company_id` 在 06 关系表里既没做过主体、也没做过客体：

| company_id | 企业 | 类型 |
|---|---|---|
| CO_ALB | 雅保 Albemarle | 矿业 |
| CO_RIO | 力拓 Rio Tinto | 矿业 |
| CO_BHP | 必和必拓 BHP | 矿业 |
| CO_VALE | 淡水河谷 Vale | 矿业 |
| CO_PILB | 皮尔巴拉 Pilbara | 矿业 |
| CO_LYNAS | 莱纳斯 Lynas | 冶炼 |
| CO_MP | MP Materials | 矿业 |
| CO_BYD | 比亚迪 | 电池 |

**为什么**：它们都是行业里绕不开的名字，但图上没有任何连接——中心性、社区发现这类图算法对孤点完全无效；评审看到"8 个孤点"一定会问。

**怎么改**：在 06 表补 1–2 条边，比如 `CO_RIO 供应 CO_GANF`、`CO_ALB 控股 CO_xxx`、`CO_BYD 供应 CO_xxx`。
若只是背景实体，就在数据字典里注明"仅背景实体"，C 会在校验报告里说明。

**谁改**：A｜**依赖**：无｜**C 侧**：重跑，孤立节点 8 → 0

### A2 ★「矿 → 企业」的供应边太少，断供推演会没戏（P1，最高性价比）

**证据**：06 表 30 条"供应"里，**20 条是企业→企业**（电池厂→车企），只有 **10 条是矿→企业**：

| 矿种 | 下游企业 | 条数 |
|---|---|---|
| 锂 | 赣锋锂业、天齐锂业 | 2 |
| 钴 | 华友钴业、洛阳钼业 | 2 |
| 镍 | 青山控股、华友钴业、住友金属矿山 | 3 |
| 稀土 | 北方稀土、中国稀土集团 | 2 |
| 锰 | 德方纳米 | 1 |
| **石墨** | **无** | **0** |
| **铜** | **无** | **0** |

**为什么**：⑤ 断供推演沿"国家 → 矿 → 企业 → 企业"往下走。石墨、铜走一步就断链；刚果金钴断供只能推出 **2 家**受影响企业。"影响 2 家"和"影响 12 家"，演示效果差一个量级。

**怎么改**：每个矿种补 3–5 条 `M_xx 供应 CO_xx`，优先补断链的两个：
- 石墨 → 负极材料企业（贝特瑞、璞泰来、杉杉股份）
- 铜 → 铜箔/线缆企业（嘉元科技、诺德股份）

新企业**先加进 02 表**（带 `alias` 和 `ticker`，C 才能做实体对齐），再在 06 引用。

**谁改**：A｜**依赖**：新企业需先入 02 表｜**C 侧**：重跑，⑤ 影响面数字变好

### A3 `出口至` 建议加一列 mineral_id（P2）

**证据**：17 条"出口至"只有起终点，矿种只写在 `note` 里；`中国→日本` 有**两条**（稀土 30%、石墨 20%）。

**为什么**：C 现在从 note 用关键词判定矿种，17 条全部唯一命中，能跑；但这是"下游猜上游"，note 措辞一变就失效。更严重的是——两条同端点边若不按矿种区分，导入时会被合并成一条，**20% 的稀土出口数据静默消失**。

**怎么改**：06 表加 `mineral_id` 列（填 `M_xx`），17 行补齐。
**C 侧已兼容**：脚本会优先读这一列，没有才回退到 note 判定。

**谁改**：A｜**依赖**：无｜**C 侧**：零改动

## 2. 给 B 组（Schema 口径与实体对齐）

### B1 ★「控股」判据和数据打架，且「参股」一条都没有（P1）

**证据**：06 表 5 条"控股"：

| 记录 | 主体 → 客体 | 比例 | note 原文 |
|---|---|---|---|
| R0188 | 天齐锂业 → SQM | 22% | 持股约 22%，为**第二大股东** |
| R0189 | 大众集团 → 国轩高科 | 24.9% | 参与定增成为**第一大股东** |
| R0190 | 中国 → 中国稀土集团 | 100% | 国资委履行出资人职责 |
| R0191 | 中国 → 北方稀土 | NA | 经包钢间接控股（推算，待核） |
| R0192 | 宁德时代 → 湖南裕能 | NA | 战略持股（推算，待核） |

而 Schema 2.2 写的口径是：**>50%，或虽不足 50% 但为第一大股东且形成实际控制**才算控股，其余记参股。

**为什么**：
1. 天齐 22%、第二大股东，按 B 自己的口径应记**参股**——现在图上的结论是"天齐控股 SQM"，Q5 穿透查询会给出错误答案。
2. 大众 24.9% 是第一大股东，**是否实际控制需组内判定**，现在直接记了控股。
3. 更关键：Schema 设计了 **10 种**关系，图里只落地 **9 种**——`INVESTS_IN` 是 **0 条**。评审问"参股这条设计怎么用"，现在答不上来。

**怎么改（二选一）**：
- **推荐**：R0188 谓词改"参股"；R0189 按判定结果二选一。这样 10 种关系齐全，判据自洽。
- 备选：改文档承认"持股即记控股"——与常识冲突，答辩易被打。

**谁改**：B 定结论 → **A 改 06 表两行**｜**依赖**：无｜**C 侧已兼容**（已支持"参股 → INVESTS_IN"），重跑即生效
